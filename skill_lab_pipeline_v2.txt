SKILL LAB + WARRIOR SKILL PACK - DEVELOPMENT PIPELINE (PoE2-INSPIRED)
Version: 2.0
Author: ChatGPT (Codex edits)

Goal: Ship a component-driven Skill Lab that mirrors Path of Exile 2 pacing, while delivering a Warrior launch kit. Designers can compose skills live, test on dummy scenarios, and export/import data. Supports, statuses, VFX, and movement all share a single data source so future archetypes plug straight into the same tooling.

-------------------------------------------------------------------------------
BIG PICTURE SUMMARY
-------------------------------------------------------------------------------
- Outcome: Fully data-driven skills with a live in-game editor (Skill Lab). Designers can create, duplicate, reorder, and tune skill components (geometry, motion, timing, damage, status, VFX) and test immediately against spawnable dummy sets. Warrior presets (Heavy Strike, Cleave, Ground Slam, Sweep, Leap Slam, Shield Charge, Lunge) arrive as tuned examples.
- Inspiration: Path of Exile 2 cadence; high-APM mapping potential but clear, dodgeable early game. Tag-first approach keeps the future support gem system trivial.
- Keys:
  - Component-based SkillData schema with motion limits, dedup pools, and VFX overrides.
  - Immutable support overlay producing DerivedSkills; editor shows live diffs, base data stays untouched until commit.
  - MovementAPI covers dash/leap/lunge actions; executor schedules components in order and runs on a fixed-tick sim when requested.
  - QA harness with deterministic toggle, DPS/TTK metrics, and export/import validation keeps "done" objective.

Non-Goals (this pipeline):
- No bespoke character animation layering beyond basic triggers.
- No netcode or multiplayer sync.
- No final art/audio production; VFX are procedural.
- No passive tree or ascendancy systems (only unlock GUI scaffolding).

Quality Bars (global):
- Smooth feel: no micro-teleporting, movement components respect collisions.
- Deterministic hits: gizmos match actual overlap tests; fixed-tick option available.
- Autosave drafts every 2s; commit workflow writes explicitly; undo stack (20 steps) never corrupts data.
- Instrumentation: rolling DPS/TTK, hit counts, status uptime, AoE coverage approximations, with reset hooks.

PHASE 1 [X] - FOUNDATIONS & SCHEMAS (DATA-FIRST)
-------------------------------------------------------------------------------
Objective: Establish component-based schemas, registries, and persistence pipeline so every system reads the same source of truth.

Tasks:
1.1 Define schemas (TypeScript)
    - SkillData (v1.1) and SkillComponent typed as:
      type SkillData = {
        schemaVersion: "1.1";
        id: string;
        name: string;
        levelReq: number;
        tags: string[];
        baseKind: "weapon" | "spell";
        baseMult: number;
        cost: number;
        cooldown: number;
        components: SkillComponent[];
        statusDefaults?: StatusDefaults;
        vfxDefaults?: VfxDefaults;
        editor?: { iconPath?: string; color?: string; notes?: string };
      };

      type SkillComponent = {
        id: string;
        timing: {
          start: number;
          duration?: number;
          tickRate?: number;
        };
        shape?:
          | { type: "circle"; radius: number }
          | { type: "cone"; angle: number; range: number }
          | { type: "line"; length: number; width: number }
          | { type: "projectile"; speed: number; lifetime: number; count: number; pierce?: number; chain?: number; pattern?: "straight" | "spread" | "return" }
          | { type: "ring"; inner: number; outer: number; expandRate?: number }
          | { type: "custom"; ref: string }; // omit for movement-only components
        motion?: {
          kind: "none" | "followCaster" | "followTarget" | "arc" | "dash";
          params?: Record<string, number>;
        }; // provide motion for movement-only components or moving hit volumes
        limits?: {
          maxTargets?: number;
          perTargetCooldownMs?: number;
          groupId?: string;
        };
        status?: Partial<StatusDefaults>;
        vfxOverrides?: Partial<VfxDefaults>;
        damage?: {
          baseMult?: number;
          addedFlat?: number;
          critOverride?: number;
        };
      };

      type MovementAction =
        | { type: "dash"; distance: number; speed: number; stopOnCollision: boolean; targeting: "forward" | "cursor" | "target" }
        | { type: "leap"; distance: number; airtime: number; allowPassThrough: boolean; targeting: "cursor" | "target" }
        | { type: "lunge"; maxDistance: number; speed: number; stickToTarget: boolean }
        | { type: "custom"; ref: string; params?: Record<string, unknown> };

      type StatusDefaults = {
        bleed?: { pctOverTime: number; dur: number; stacksMax: number };
        shred?: { drPctPerStack: number; dur: number; stacksMax: number };
        stun?: { chance: number; dur: number };
        knockback?: { meters: number; immunityMs?: number };
      };

      type VfxDefaults = {
        palette?: string;
        trail?: { width: number; duration: number };
        impact?: { type: "circle" | "line" | "burst"; size: number; color?: string };
        particles?: { count: number; size: number; lifetime: number };
        screenShake?: { amplitude: number; duration: number };
        // global time-dilation toggle lives in editor, not schema.
      };

1.2 Migration harness
    - Add schemaVersion to persistence; create migration stub (v1.0 -> v1.1) converting single shape fields into component arrays.

1.3 Support operation phases
    - Define SupportOp as { target: string; op: "multiply" | "add" | "clampMin" | "clampMax" | "set" | "push"; value: unknown; phase: "pre" | "main" | "post" }.
    - Implement immutable applySupports(baseSkill, supports[]) returning DerivedSkill with canonical order: pre -> main -> post -> penalties.

1.4 Registries
    - skills.registry.ts: load warrior presets with components, placeholders for future archetypes.
    - supports.registry.ts: seed IncreasedAreaSupport, MoreMeleeSupport.
    - statuses.config.ts: default tuning per status type.

1.5 Persistence utilities
    - Autosave drafts (localStorage namespace skillLab.drafts.v1).
    - Commit writes to runtime profile JSON (skillLab.commits.v1); provide guarded "Write to source" flow for deliberate preset updates.
    - Import/Export JSON with schema validation.

Deliverables:
- /src/skills/skills.schema.ts
- /src/skills/migrations/v1_0_to_v1_1.ts
- /src/skills/skills.registry.ts
- /src/supports/supports.registry.ts
- /src/utils/persistence.ts

Acceptance tests:
- Schema validation passes for warrior presets.
- Migration converts v1.0 sample data to v1.1 components.
- applySupports does not mutate base skill and respects phase ordering.
- Autosave/commit round trip preserves data integrity.

PHASE 2 [X] - EXECUTOR, GEOMETRY, MOVEMENT, METRICS
-------------------------------------------------------------------------------
Objective: Build a deterministic SkillExecutor that schedules components, drives MovementAPI, resolves hits, and feeds the metric pipeline.

Tasks:
2.1 Component scheduler
    - Sort components by timing.start; queue tick events for duration/tickRate; emit execution events.

2.2 Hit geometry utilities
    - spawnCircle, spawnCone, spawnLine, spawnRing, spawnProjectile; each exposes drawGizmo(ctx) and overlapTest(entity, dt).
    - Support limits.maxTargets and groupId dedupe.

2.3 MovementAPI
    - Implement dash/leap/lunge handlers honoring targeting rules and collisions (swept tests, stopOnCollision).
    - Provide callbacks (onStart, onLand, onCancel) for executor.

2.4 Fixed-tick simulation
    - Add toggle to run executor under deterministic fixed timestep (default 60Hz) with seedable RNG.
    - Ensure movement and hit resolution align between variable and fixed modes.

2.5 Damage model
    - Introduce armor mitigation (simple physical DR curve) and crit chance/damage defaults.
    - Emit HitEvent with hooks for StatusSystem and metric logging.
    - Define preHit -> onHit -> postHit hooks so statuses, lifesteal, on-kill, etc. plug in without touching executor internals.

2.6 Metric pipeline
    - Rolling DPS window (last 5 seconds) and TTK (average of last N dummy kills).
    - Reset hooks (manual and on skill change).
    - Persist recent logs for editor panel.

Deliverables:
- /src/skills/SkillExecutor.ts
- /src/skills/HitGeometry.ts
- /src/skills/MovementAPI.ts
- /src/metrics/SkillMetrics.ts

Acceptance tests:
- Each shape hits stationary and moving dummies; gizmo overlays match actual hits.
- Movement actions respect collisions and targeting; leap lands near cursor, dash stops on wall, lunge tracks target.
- Fixed-tick mode reproduces results across repeated casts (checksum logs match).
- Hit dedup ledger key = (castId, targetId, groupId); ledger resets per cast and never suppresses later casts.
- Armor/crit hooks modify damage as expected (unit tests or scripted harness).
- Metrics update correctly after resets and during spam.

APPENDIX A - DEFAULT BASELINES
-------------------------------------------------------------------------------
- Ranges: melee 3.0m; small AoE 4.5m; large AoE 6.5m; cone 75 deg;  line 6m x 2m.
- Pacing: basic cooldown 0.7s; mid cooldown 3-5s; mobility 6-8s.
- Costs: basic 8-10 mana; mid 15-20; mobility 12-15.
- Status: bleed = 80-120% over 4s (max 3 stacks); shred = -10% DR per stack (3 stacks, 3s); stun = 25% chance, 0.6-0.9s; knockback = 1.5-2.5m with 300ms immunity.
- Metrics: default rolling windows DPS 5s, TTK average last 3 kills.
